# Releasing

A release is one Git tag. Pushing `vX.Y.Z` builds and publishes everything:
daemon and CLI archives with installers, desktop installers for macOS, Linux
and Windows, and the manifest the desktop updater reads.

## Cut a release

```sh
scripts/release.sh 0.2.0
```

The script refuses a dirty tree or a branch other than `main`, then bumps the
workspace version in `Cargo.toml` (every crate inherits it), the Tauri bundle
version in `apps/desktop/src-tauri/tauri.conf.json` and `apps/desktop/package.json`,
refreshes `Cargo.lock`, commits `release: v0.2.0`, tags `v0.2.0` and pushes both.
`--no-push` stops after the local commit and tag. A `-beta.1` style suffix
marks the GitHub Release as a pre-release; the updater still offers it, so use
pre-releases only for versions you want every installed app to pick up.

Watch progress at <https://github.com/Tresnanda/kybern/actions>.

## What runs

1. **`release.yml`** (generated by [dist](https://axodotdev.github.io/cargo-dist/)
   from `dist-workspace.toml`; regenerate with `dist generate` after editing
   that file) builds `kybernd` and `kybern` for macOS (Apple silicon, Intel),
   Linux (x86_64, arm64 musl) and Windows, writes `kybern-daemon-installer.sh`,
   `kybern-cli-installer.sh`, their PowerShell twins and the
   `kybern-daemon-update` / `kybern-cli-update` self-updaters, and creates the
   GitHub Release.
2. **`desktop.yml`** runs afterwards as dist's post-announce job. One job per
   platform builds the app with its bundled daemon and uploads:
   - macOS: `kybern-<v>-<arch>-apple-darwin.dmg` plus the signed updater
     tarball `.app.tar.gz` and `.sig`, produced by `scripts/bundle-macos.sh`
     (ad-hoc signed, not notarized).
   - Linux: `kybern-<v>-x86_64-unknown-linux-gnu.AppImage` (+ `.sig`) and `.deb`.
   - Windows: `kybern-<v>-x86_64-pc-windows-msvc-setup.exe` (+ `.sig`, NSIS).

   `scripts/desktop-artifacts.mjs` renames the bundles and records each
   platform's download URL and signature; the final `manifest` job merges them
   with `scripts/updater-manifest.mjs` into `latest.json` and uploads it together
   with `kybern-remote-install.sh`, the daemon-only installer for VPSes.
3. **Installed apps** poll
   `https://github.com/Tresnanda/kybern/releases/latest/download/latest.json`
   15 seconds after launch and every six hours, verify the artifact against the
   public key in `tauri.conf.json`, and offer **Update and restart**. After the
   relaunch the shell notices the bundled daemon is newer than the running one
   and restarts it. **Settings → About** shows the app version and has a
   manual check.

`workflow_dispatch` on the Desktop workflow builds every platform as a dry run
and keeps the bundles as workflow artifacts without touching a release.

## One-time setup

- **Updater signing key.** Generated with
  `pnpm tauri signer generate -w ~/.tauri/kybern.key` (no password). The public
  half is committed in `tauri.conf.json`; the private half is the repository
  secret `TAURI_SIGNING_PRIVATE_KEY`, with `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
  set to an empty string. Losing the private key means installed apps can never
  accept another update, so keep `~/.tauri/kybern.key` backed up. Rotating it
  requires shipping the new public key in an app that users install by hand.
- **Repository visibility.** GitHub only serves release assets of a private
  repository to authenticated requests. Installed apps and the `curl | sh`
  installers fetch anonymously, so the repository (or a separate public
  releases repository that the workflows publish to) must be public before the
  updater and remote installer work.
- **Runners.** `macos-15`, `macos-15-intel`, `ubuntu-22.04` (older glibc keeps
  the AppImage portable) and `windows-2022`, all GitHub-hosted.

## Checking a release

- The release page lists the assets above plus `latest.json`, whose
  `platforms` keys are `darwin-aarch64`, `darwin-x86_64`, `linux-x86_64` and
  `windows-x86_64`. A platform whose build failed is missing from the manifest
  and its job is red; rerun the failed job and the manifest job.
- Install the previous version, launch it, and confirm the toast and the About
  row offer the new one.
- On a scratch VPS, run the remote installer with `--service` and then
  `kybern pair`.
