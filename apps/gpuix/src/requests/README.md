# Request cards

Every request that waits on the reader is one family (Direction B, "Option list"): header, the well that shows what is asked,
numbered rows, a hint line. Spec and tokens: `.kybern-artifacts/ade-approval-design/` (`spec.md`, `motion.md`, `src/req.css`).

| File | What |
| --- | --- |
| `model.ts` | `approvalCard(approval, provider)`: title, well and the rows (label, RPC) of every tool approval and consent kind. The rows, the key map and the RPC come from this one table, so they cannot drift. `sessionLabel` words the session option for what each harness really allows (Claude's suggested rules, prefix rules as "… commands"; OpenCode's patterns; Codex's exact command or edited files; Pi's exact call only through Kybern's extension; Cursor's own "always" option), and leaves it out when the harness would only approve once. |
| `shell.ts` | Splits the real `input.command` on `&&`, `\|\|`, `;`, `\|`, `\|&`, `&` and newlines (quotes, `$(…)`, backticks, `((…))`, `[[ … ]]`, `case` terminators, heredocs and comments are not split) so `a && b` never reads as `a`. Display only: no allow rule is built from a segment. A command that is not a plain chain, or a split that would lose a character, stays whole. |
| `actions.ts` | `chooseRow`, `sendDecline`, `cancelTurn`, `handleCardKey`: what a click, a digit or a key does. The card and the composer share them. The harness is the one of the approval's own thread, not the focused pane's. |
| `ui.ts` | Highlight, open note, choice in flight, expanded well; module state because the composer also routes keys. |
| `Card.tsx` | Header, wells (`CodeWell`, `DiffWell`, `PlanWell`, …), `OptionRow`, `NoteField`, `Hints`. One content inset for every card: the rows bleed 8 into the 16 gutter (tint at x 8, radius 10), the digit or checkbox is centred in a 24 column at x 16, and the header title and every row label start at x 50; hints sit at x 16 and actions end at W − 16. |
| `ApprovalCard.tsx`, `Question.tsx`, `Secret.tsx`, `../coordinator/Cards.tsx` | The card kinds built from those parts. A question reads the daemon's normalized `questions` (`packages/kybern-client/src/userInput.ts`); spec `.kybern-artifacts/ade-69-71/qcard/spec.md`. Its first paragraph, as plain text, is the title and the rest a bounded Markdown body (`splitQuestion`); the header word and "2 of 3" show only with several questions. The first row (or the deadline's default) is focused and picked on arrival; the last row, "Something else…", becomes the answer field in place (↵ sends, ⇧↵ new line, esc back with the draft kept). The focused option's `preview` sits beside the rows when the card itself is 640 pt or wider (A), else under the focused row, clamped at 6 lines (B, ⌘E). Attach (image, window capture, file) is an icon button holding attachments per question, and the answer goes as `kybern_answers`, which the daemon turns into the harness's own response. One question sends; several go Next, Review, Send, with Back. |
| `attach.ts` | The capture path "Point for me" and a question's Attach share: image types, uploads, the system window capture. |
| `Pick.tsx` | `kybern_request_pick` ("Point for me"): an element pick is a choice card (rows, then a status line while the page waits, then a confirm with a crop); a file or folder (tree), an image (drop zone) and a window (`screencapture -i`) are closed forms. The overlay is drawn in the page by `../pick/pickerScript.ts`, run in the isolated preview world through the `frame` and `snapshot` ops of `native/webview.m`; `../pick/hub.ts` finds the live documents, bounds what a page sends and makes the ⌥-click anchor chip; `../pick/controller.ts` drives a card's pick. A page's text and HTML are data, never instructions. Live check: `bun src/pick/pick.verify.ts secret|pick|anchor|kinds` (see its header). |
| `Login.tsx`, `Prompt.tsx`, `Permission.tsx`, `Deadline.tsx` | The daemon's summoned cards (ADE-69..71): sign-in (`kybern_request_login`), the password prompt (`kybern_askpass`, always a closed form that always rises in), the macOS permission (`kybern_request_permission`) and a question's countdown (`input.deadline`, never on approvals). Copy, inputs, countdown math and transcript records are shared in `packages/kybern-client/src/requestCards.ts`. |
| `progress.ts` | `RequestProgress` keyed by approval id: the `requests.progress` notification, a list read on connect and on card mount, forgotten on `approval_resolved`; `actOnRequest` is `requests.act`. A `terminal` item opens its terminal as a tab (`tabs/open.ts` `openTerminalTab`). |
| `choices.tsx`, `summoned.tsx`, `glyphs.ts` | Rows that run their own action (`useChoices`, `ChoiceRows`, keys shared with the empty composer through `registerCardKeys`), the phase fade, "14:12 left", inline code text, and the service and pane glyphs. |

Keys: digits follow the visible order and Decline is always the last number. ↑ ↓ move the highlight (in the empty composer they hand
the keyboard to the card), Return picks the highlighted row only with the card root focused (never from the composer, a link or a
field inside the card), Esc cancels the turn (forms ignore it; an open kit overlay or the palette keeps it), ⌘E expands a clamped well.
Keys from a composer of another thread are ignored. A card that arrives while someone is typing never takes focus.

Decline opens a note field in the row. Claude's driver and the daemon's own cards (computer use, notes and tasks) carry the note as the
deny `reason`; every other driver drops it, so the note also goes as the next queued message.

Checks: `bun test src/requests`, `bun src/requests/summoned.verify.ts` and `SHOT_THEMES=dark,glass-dark bun src/requests/summoned.shots.ts` (summoned cards), `bun src/requests/keys.verify.ts` (native fixture; keys and notes), `SHOT_TAG=after SHOT_THEMES=dark,glass-dark bun src/requests/shots.ts`,
`QCARD_THEMES=dark,light,glass bun src/requests/qcard.shots.ts` (the question card's states on `qcard.fixture.tsx`, with its keys asserted).
Run the fixtures with `NAPI_RS_NATIVE_LIBRARY_PATH` set to a patched addon.

Typing guard (`typingGuard.ts`, `TypingHint.tsx`): a card that would replace the composer (question, password, secret, pick, proposal) waits while the reader types: a hint above the composer stands in until the composer has been still for 1.5 s (Esc or a click opens it at once; a password or secret ignores Esc). The draft is kept by `composer/drafts.ts`; a question's deadline is paused while held. `typing.verify.ts` drives it.
