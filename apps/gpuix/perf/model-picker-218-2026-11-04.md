# Model picker: typing and scrolling over a large catalog (#218, 2026-11-04)

Workload: `scripts/model-picker-lab.tsx`, the shipped `ModelPicker` over a 600-model OpenCode-style catalog (twelve
backends, so the list is grouped; every other model has a description line). `scripts/model-picker-perf.ts` opens it and:

- types `gemini flash 2` three times into the search (42 keys, 120 ms apart, through the automation `keystrokes` call),
  timing each key from the moment it is sent to the first presented frame (`[kybern-frame]`, GPUI's `present`) after the
  picker's React commit for it (`[lab-commit]`, a Profiler). Boundary: input sent → JS change → commit → next present;
  not the compositor or the display. `commitMs` is React's own render time for that commit;
- searches `r` (150 results shown, the cap) and wheels over the list every 16 ms for 2 s (down, then up), three times,
  recording the intervals between presented frames.

Machine: SatyaMas, Windows 11, Ryzen 7 5800H, NVIDIA GeForce RTX 3060 Laptop GPU (GPUI took DXGI adapter 0, the RTX;
the AMD iGPU is only selectable through the per-app Windows graphics preference, which was left alone, so it was not
measured). Release builds of the addon (the 0.21.6 one before; the `issue-218` fork commit without LTO after). Bun 1.4.3.

| | Before (main, 0.21.6 addon) | After (this branch) |
| --- | --- | --- |
| Key to paint p50 / p90 / max, dark | 52.3 / 62.7 / 109.6 ms | 10.3 / 16.3 / 23.7 ms |
| Key to paint p50 / p90 / max, light | 48.8 / 72.1 / 110.8 ms | 9.7 / 13.0 / 17.1 ms |
| React commit per key p50 / p90, dark | 4.7 / 8.6 ms | 2.5 / 3.6 ms |
| Frame interval while scrolling p50 / p90 / max, dark | 56.6 / 62.9 / 74.2 ms (104 frames, all > 33 ms) | 6.8 / 11.4 / 21.5 ms (851 frames, none > 33 ms) |
| Frame interval while scrolling p50 / p90 / max, light | 56.7 / 62.8 / 67.6 ms (103 frames) | 6.9 / 11.6 / 23.2 ms (847 frames) |

The new picker on the 0.21.6 addon measures the same as "after" (key to paint p50 11.1, p90 18.1 ms; scrolling p50 7.0 ms),
so the gain is the list, not the native focus fix. React was never the main cost (≈5 ms a key): GPUI laid out and painted
all 150 rows every frame. A large catalog's list is now a native `<virtual-list>`, which lays out and paints only the rows
near its viewport, and the rows are memoized so a keystroke that keeps a row does not rebuild it.

Before, a wheel step is a waited bridge call, so the slow frames also meant fewer wheel steps reached the list in the same
2 s; the frame counts are not a like-for-like scroll distance. Screenshots: the open picker, the results and the list at the
turn of the first scroll pass, dark and light, under `--out`.
