# In-thread tabs (ADE-54) vs today's dock: switching and a 2×2 (2026-10-23)

`bun perf/tabs-ade54.ts tabs 3` and `bun perf/tabs-ade54.ts dock 3` (raw rows: `tabs-ade54-tabs.json`,
`tabs-ade54-dock.json`). Same scratch daemon (`src/tabs/verify.ts` seeds it), same window (1440×900, opaque, dark,
motion on, `GPUIX_BACKGROUND=1`), same patched `@gpuix/native` 0.11.0 build. "Dock" is `main` @ v0.11.1 (`a16da429b`)
in a scratch checkout sharing this checkout's dependencies; "tabs" is this branch. Apple M1, macOS 27.0.1. Medians of
three runs, with the range.

## Workload

1. **Switching.** The 30-turn "Long review thread". Tabs: the chat, `src/Explorer.tsx` and the change set as tabs;
   30 alternations ⌘2 / ⌘1 (document, chat), one every 350 ms. Dock: the same thread with the Explorer (file open) and
   Changes panes; 30 alternations between the two panes, chat visible. Not the same gesture: each is how the build
   puts a document beside the chat.
2. **2×2.** Tabs: four groups (the long thread's chat; its two files; its diff and a Markdown file; another thread's chat),
   focus on the file group. Dock: four threads in a 2×2, the dock open on the focused one. 15 s idle, then 20 switches
   (tabs: ⌃Tab between two files; dock: Explorer ↔ Changes panes).

Measured: CPU time (`ps`), physical footprint (`footprint`), presented frames (`KYBERN_FRAME_TIMES`; intervals over
250 ms are the idle wait between two switches and are left out of the percentiles), and the key-or-click to content
latency seen by the automation driver (includes its round trips).

## Reading it

- A tab switch is instant by spec (§1.5: no motion on content), so it presents ~3–4 frames; a dock pane switch plays the
  250 ms `t-pane` entrance (~19 frames). That, not layout, is most of the dock's 3.3× CPU.
- The chat stays mounted under a document tab (opacity 0, no pointer events), so ⌘1 neither rebuilds the transcript nor
  loses the reading position. Before that change the first measurement showed a 316 ms frame on every ⌘1 and 3.9 s of
  CPU for the 30 switches (the file viewer also replayed its entrance; both fixed in `5f621f9ae`).
- Idle cost is unchanged: a hidden chat, inactive tabs and lower-group strips cost nothing while nothing changes
  (1 frame in 15 s). Inactive document tabs are unmounted; terminals keep their daemon session and replay on mount.
- The cost that remains is the **document mount**: switching to a file tab re-reads the file and builds its syntax
  document, ~125 ms of CPU, presented as three or four 40–60 ms frames in a 2×2 (the whole window lays out each frame).
  The dock avoids it in this workload only because its Explorer pane forgets the open file. A per-thread cache of the last
  read file and its syntax document would remove it; not done here.
- Footprint grows ~20–25 MB over the first switches (syntax documents and file reads) and then holds: 150 switches end
  at the same +20 MB as 30 (248 → 268 MB). The 2×2 with one thread's documents in three groups uses less than four
  threads in a 2×2 (257 vs 277 MB) because one transcript is shared.

## Limits

- One machine, background windows (frames may be throttled when occluded), automation-driven input; latency includes
  the driver's polling (5 ms) and IPC.
- The two builds do different things for "switching"; the comparison is "how each build shows a document next to the
  chat", not the same code path.
- WKWebView pages (browser tab, visuals) are outside GPUI and are not in these numbers.

## File tab cache (review follow-up, same day)

`src/dock/fileCache.ts` keeps the last 8 file reads and 8 syntax documents per window (LRU; an evicted document is
released once no viewer holds it). A file viewer draws a cached read and document on its first render and re-reads in
the background; an unchanged read keeps the cached object, so nothing is rebuilt. Same machine, scratch daemon and
window as above, patched addon with the ADE-58 backdrop fix; medians of three runs (raw rows in
`.kybern-artifacts/ade-54-58/review/perf-*.json`, not committed).

| Workload | Before | After |
| --- | --- | --- |
| Switching, `src/Explorer.tsx` (9 lines): CPU / frames for 30 switches | 2.01 s / 111 | 1.99 s / 84 |
| 2×2, two 1–9 line files: CPU for 20 ⌃Tab | 2.69 s | 2.62 s |
| Switching, a 1,113-line TSX file (`FILE=src/Big.tsx CONTENT=1`): CPU / frames for 30 switches | 6.79 s / 287 | **2.48 s / 98** |
| Same, ⌘2 to highlighted code on screen, p50 / p95 | 269 / 290 ms | **54 / 65 ms** |
| Same, footprint after the 30 switches | 288 MB | 273 MB |

- With a realistic file the mount cost was the read plus the syntax document: about 290 ms of CPU per ⌘2 (15 of the 30
  switches), now gone; ⌘2 costs what ⌘1 costs. The fixture's 9-line files hid it, so the earlier "~125 ms" figure for
  them was mostly the whole-window layout of the 2×2, which this does not change (its 40–60 ms frames remain).
- The background re-read still runs on every mount (one `files.read`), so an edited file shows its new text; only an
  identical read skips the rebuild.
