# Zeron / Zed techniques and the GPUIX performance plan

Research lane `gpuix/perf-research`, GPUIX baseline `ef2251e2`, 2026-10-18.
Research and measurement helpers only; no product/native change or new performance default.

## What matters most

The useful pattern is **bounded visible work, stable document identity, and precise invalidation**. GPUI does not automatically make a large retained React tree cheap. Zed's list callbacks instantiate visible rows on demand; Zeron splits a reply into semantic blocks, incrementally parses the changing tail, prepares presentation off the UI thread, and releases derived paint data outside its viewport. GPUIX has native viewport culling and substantial paint/layout machinery already, but most transcript/sidebar/tree callers still instantiate all their React children.

Two corrections prevent wasted implementation:

- Zeron's sidebar is **not** a `uniform_list` at this revision: it builds grouped children in an ordinary scrolling div, inside a cached `SidebarPane`. Its transcript and Markdown-file preview use variable-height `list`. Zed's project panel uses `uniform_list`. Copy the relevant technique per surface; do not describe every Zeron surface as virtualized.
- Neither current Zed Markdown nor GPUI scrolling universally avoids layout. Zed's Markdown element walks the parsed event collection and builds a child tree; GPUI `List` renders/measures visible elements again when redrawn. GPUIX's existing PR root-relative geometry reuse goes beyond basic GPUI here. The remaining opportunity is to extend it safely and reduce the amount of materialized content, not replace it with generic cached wrappers.

These are source findings, not measured proof that either reference app holds 60/120 fps in every workload. No Zed/Zeron runtime was built or benchmarked.

## Technique catalogue

### T1. Build a viewport, rather than all rich rows

**Zed fixed-height lists.** `uniform_list` calculates first/last row from scroll offset, viewport and row height, calls the renderer for that range, then lays out/prepaints those rows. One representative item can additionally be built to measure size. For a 600px viewport and 28px rows, the normal range is about 22–23 rows, plus a measurement row when needed; this is a calculation, not a measured universal row count. Zed's project panel forwards the range and records `rendered_entries_len`, so it avoids building every expanded file entry. Sources: [Z:crates/gpui/src/elements/uniform_list.rs:475–514](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/uniform_list.rs#L475-L514), [Z:crates/gpui/src/elements/uniform_list.rs:654–684](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/uniform_list.rs#L654-L684), [Z:crates/project_panel/src/project_panel.rs:7684–7710](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/project_panel/src/project_panel.rs#L7684-L7710).

**Variable-height lists.** `ListState` retains measured heights and a summary tree. It builds visible rows, measures unknown heights in trailing/leading pixel overdraw, and can build a focused item outside the viewport. Thus the count depends on actual heights, cache warmth, viewport, focus and overscan; it is not a constant or necessarily one callback per row per frame. For equal 28px rows with 320px overdraw each side, a rough cold measurement window at 600px is 45 rows. A giant Markdown row still builds its entire internal content. Sources: [Z:crates/gpui/src/elements/list.rs:1052–1205](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/list.rs#L1052-L1205), [Z:crates/gpui/src/elements/list.rs:1251–1355](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/list.rs#L1251-L1355).

**Zeron.** Transcript rows are semantic blocks, with stable IDs across streaming completion; overdraw is 320px. Markdown-file preview similarly uses block rows and a 400px ListState overdraw. Sources: [R:crates/ui/src/transcript.rs:1–25](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L1-L25), [R:crates/ui/src/transcript.rs:61–78](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L61-L78), [R:crates/ui/src/transcript.rs:10318–10329](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L10318-L10329), [R:crates/ui/src/files/markdown_preview.rs:440–453](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/files/markdown_preview.rs#L440-L453), [R:crates/ui/src/files/markdown_preview.rs:1397–1421](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/files/markdown_preview.rs#L1397-L1421).

**GPUIX: partial.** Native `virtual-list` calls `build_virtual_child` only for GPUI-requested rows, but React has already created every supplied child and its rich subtree. `Transcript.tsx:104–143,248–291`, `Sidebar.tsx:131–150`, and `dock/MotionFileTree.tsx:15–29` all map the complete current row array. Sidebar initially caps top-level project threads at eight (`sidebar/model.ts:1–22`), but expanding projects, Recents, children and older history still grows retained work. ### T2. Cache views by entity and notify only the owner

GPUI cached views require definite geometry. Their cache key checks bounds, content mask and text style plus dirty entity/window refresh state; replay reuses prepaint/hitboxes, accessed entity dependencies and paint ranges. `cx.notify()` invalidates the backing entity. A blanket window refresh defeats reuse. Sources: [Z:crates/gpui/src/view.rs:250–259](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/view.rs#L250-L259), [Z:crates/gpui/src/view.rs:530–589](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/view.rs#L530-L589), [Z:crates/gpui/src/view.rs:615–640](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/view.rs#L615-L640).

Zeron gives sidebar rendering its own entity, cached at resolved sidebar width; it deliberately observes Shell for real navigation/theme changes. Small spinners get distinct cached entities whose props notify only on a real change. Pure transcript text growth has a separate `TranscriptTextChanged` event, and session presentation comparison ignores lease-only timestamp churn. Sources: [R:crates/ui/src/shell.rs:1928–1952](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/shell.rs#L1928-L1952), [R:crates/ui/src/shell.rs:7735–7759](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/shell.rs#L7735-L7759), [R:crates/ui/src/loaders.rs:202–225](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/loaders.rs#L202-L225), [R:crates/ui/src/state.rs:881–893](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/state.rs#L881-L893), [R:crates/ui/src/state.rs:1197–1218](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/state.rs#L1197-L1218).

**GPUIX: largely present, invalidation still partial.** `native/patches/cache_island.rs:160–238,308–356` exposes cached entities and revision-based wakeup; ordinary changes propagate subtree revisions through every retained ancestor ([G:packages/native/src/retained_tree.rs:217–243](https://github.com/remorses/gpuix/blob/9fcd628863e354e9c58019fc3bf38981a1e64158/packages/native/src/retained_tree.rs#L217-L243)). Scoped paint, retained translations/transforms and paint-only fades already avoid that path for their supported cases. PR viewports additionally use `independent_scroll_cache` (`scroll_hooks.py:40–55`). Do not repeat the rejected “wrap every row in more cache boundaries” experiment: `perf/idle-regression-2026-10-16.md:142–166` records worse CPU/render counts. Extend narrowly, with ordinary invalidation preserved for geometry, inherited style, children, clipping, selection and overlays.

### T3. Separate stable syntax/document data from disposable visible paint data

Zeron keeps completed row builds by entry fingerprint, invalidates only changed entry IDs, and prepares presentation in subscription background work. Streaming parsing carries a stable prefix; completion adopts the live parser's exact canonical tree instead of reparsing. A row/version diff drives minimal list splices. Sources: [R:crates/ui/src/transcript.rs:1915–1980](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L1915-L1980), [R:crates/ui/src/transcript.rs:2545–2649](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L2545-L2649), [R:crates/ui/src/transcript.rs:5250–5303](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L5250-L5303).

`RenderCache` stores shared flattened strings/text runs and code-line runs by row/block/discriminator, validates style/math generations, and retains only rows used by the last viewport. This keeps cached flatten/shaping inputs cheap without retaining every historical line. Sources: [R:crates/ui/src/markdown/render.rs:421–495](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/markdown/render.rs#L421-L495), [R:crates/ui/src/transcript.rs:10123–10140](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L10123-L10140).

**GPUIX: partial.** Settled data projection and memoized rows exist, and `markdownParts` has a bounded small-answer cache (`src/transcript/markdown.tsx:24–53`). But a changed answer is split/scanned again; native Markdown caches its parsed tree by full source hash/length and then reconstructs render elements ([G:packages/native/src/custom_elements/markdown.rs:35–61](https://github.com/remorses/gpuix/blob/9fcd628863e354e9c58019fc3bf38981a1e64158/packages/native/src/custom_elements/markdown.rs#L35-L61), [G:packages/native/src/custom_elements/markdown.rs:94–105](https://github.com/remorses/gpuix/blob/9fcd628863e354e9c58019fc3bf38981a1e64158/packages/native/src/custom_elements/markdown.rs#L94-L105)). `markdown_hooks.py:54–75` still renders all blocks of the supplied tree. Derived visible text-run caching and byte-budgeted retention deserve measurement separately from AST caching.

### T4. Reuse text shaping and wrapped lines; keep color animation out of shape keys

GPUI `WindowTextSystem` has per-frame line layout caches; current-frame hits reuse `Arc` layouts, previous-frame hits migrate to the current frame. Wrapped layouts reuse the unwrapped line plus wrap boundaries. Cached-view replay explicitly marks old layouts used; end-of-frame swaps and clears unused generations. Stable font/run/wrap keys matter. Global text caches also retain font resolution/metrics and glyph raster bounds; glyph image work can use the atlas. Sources: [Z:crates/gpui/src/text_system/line_layout.rs:523–605](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system/line_layout.rs#L523-L605), [Z:crates/gpui/src/text_system/line_layout.rs:607–689](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system/line_layout.rs#L607-L689), [Z:crates/gpui/src/text_system.rs:230–255](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system.rs#L230-L255), [Z:crates/gpui/src/text_system.rs:561–580](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system.rs#L561-L580).

Current Zed also supports caller-provided content hashes so a hit can avoid materializing a contiguous string. That is a newer optimization to investigate in the pinned fork, not an assumption about GPUIX: [Z:crates/gpui/src/text_system.rs:679–739](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system.rs#L679-L739), [Z:crates/gpui/src/text_system.rs:959–1009](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/text_system.rs#L959-L1009).

**GPUIX: present underneath, partial above.** Rebuilding equivalent run vectors still costs allocation/hash/key construction even if shaping hits. `font_weight.rs` caches CoreText variable-axis/font instances, `markdown_inline.rs` retains mixed-size run geometry within an element, and `stream_fade_gpui.py`/`stream_fade_md.rs` already animate glyph alpha using retained paint. Preserve this paint-only fade; do not add a per-frame React text-color clock. Measure cache hits, shaped bytes and wrapped lines before adding another cache. Width, scale, font generation, theme and language changes must invalidate the appropriate layer.

### T5. Native offsets and frame-coalesced input, with honest layout costs

GPUI `ListState::scroll` changes a logical item/offset using the height summary, clamps to the list, updates follow state, emits its scroll callback and notifies the current view. Its paint-installed listener coalesces deltas relative to that painted frame. This saves document reconstruction but still redraws and measures visible items; it is not universal compositor-only scrolling. Sources: [Z:crates/gpui/src/elements/list.rs:901–960](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/list.rs#L901-L960), [Z:crates/gpui/src/elements/list.rs:1590–1627](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/elements/list.rs#L1590-L1627).

OS macOS wheel events supply precise pixel deltas/contact phases; GPUI's event type does not carry a separate momentum phase. Zeron adds its own rubber-band wrapper, inferring momentum after contact end, shifting prepaint and clipping without changing the list's layout. This is behavior, not a free optimization, and should not be imported into Kybern when parity requires its existing feel. Sources: [Z:crates/gpui_macos/src/events.rs:230–266](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui_macos/src/events.rs#L230-L266), [R:crates/ui/src/overscroll.rs:1–64](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/overscroll.rs#L1-L64). Zeron's follow-tail spring is similarly a product behavior with conditional scheduling ([R:crates/ui/src/transcript.rs:17–25](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/transcript.rs#L17-L25)).

**GPUIX: partial, strong PR implementation exists.** `scroll_input.rs`, `scroll_layout.rs`, `scroll_taffy.rs` and `scroll_hooks.py` implement a single pending input slot, root-relative layout snapshots and independent PR viewport caches. Geometry reuse validates styles/topology/measurements/size/scale and expires after two offscreen frames with 128-root/16,384-node bounds (`scroll_taffy.rs:1–65,100–164`). Only PR callers pass `cacheLayout` (`src/pulls/scroll-layout.ts:1–8`). Transcript, sidebar and Explorer do not. Coalescing defaults to PR; app-wide `KYBERN_SCROLL_COALESCE=all` and skipping test-support synchronous draws with `KYBERN_INPUT_FRAME_DRAW=1` remain experiments. The historical PR measurements below support expanding this machinery under a regression gate, not blindly enabling every flag.

### T7. Self-parking clocks and cached animated islands

Zeron's pulse clock is 33ms (~30Hz); some shell glyphs take every second tick (~15Hz). Only recently painted spinner entities hold leases, expiring after 300ms. The shared phase has one epoch; absent leases park the clock. Loader cells stay in fixed slots, and cached spinner entities isolate their redraw. Sources: [R:crates/ui/src/motion.rs:47–85](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/motion.rs#L47-L85), [R:crates/ui/src/motion.rs:108–127](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/motion.rs#L108-L127), [R:crates/ui/src/motion.rs:183–255](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/motion.rs#L183-L255), [R:crates/ui/src/loaders.rs:1–11](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/loaders.rs#L1-L11), [R:crates/ui/src/loaders.rs:202–225](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/loaders.rs#L202-L225).

### T8. Long Markdown: semantic blocks and incremental tails, with cross-block semantics intact

Zeron's incremental parser reparses a suffix starting near the last two distinct top-level block boundaries, sometimes backing up a container for lazy continuation. Link-reference definitions force a full parse because they can change earlier blocks. It reports `last_parse_bytes` and `stable_prefix_blocks`. Sources: [R:crates/markdown/src/parser.rs:1996–2020](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/markdown/src/parser.rs#L1996-L2020), [R:crates/markdown/src/parser.rs:2061–2165](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/markdown/src/parser.rs#L2061-L2165).

Zeron's file Markdown preview debounces 120ms, parses/highlights on a background executor, then renders a List of blocks and trims viewport render cache. However, a single huge table/list/code block is still one block: block virtualization is not a solution to every pathological document. Sources: [R:crates/ui/src/files/markdown_preview.rs:462–525](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/files/markdown_preview.rs#L462-L525), [R:crates/ui/src/files/markdown_preview.rs:1074–1118](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/files/markdown_preview.rs#L1074-L1118), [R:crates/ui/src/files/markdown_preview.rs:1342–1350](https://github.com/zeronsh/zeron/blob/c02739da309118c2174f427511110046f0bfba16/crates/ui/src/files/markdown_preview.rs#L1342-L1350).

### T12. Frame arenas and caches have different lifetimes

GPUI allocates temporary element objects in an arena, calls destructors at clear, and resets chunks for reuse; it does not retain every immediate element indefinitely. Nested scopes defer clearing for safety. Chunk memory can remain at a high-water mark: resetting is not returning all pages to the OS. Sources: [Z:crates/gpui/src/arena.rs:133–186](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui/src/arena.rs#L133-L186). Durable entity state, measured heights, parsed documents and GPU resources are separate lifetimes.

**GPUIX: native arena present, React retention partial.** Native element disposal does not release React Fiber/retained host nodes for offscreen children that callers still mount. `cache_island.rs:91–96` prunes on retained-node removal, not merely when native paint virtualizes a row. JS row state is bounded to 2,000 entries and reset on environment change (`transcript/store.ts:31–53,360`); per-turn `diffs` and `patches` need a consistent byte/entry eviction audit (`:154–205`). Do not retain `AnyElement`, frame arena references or Taffy IDs across frames; the current scroll cache correctly retains plain geometry snapshots instead.

Backdrop scratch is quantized to 64px extents, cached across up to four pairs under an aggregate budget, and trimmed when idle/window size changes. Path intermediates and unused blur resources are dropped rather than held forever; draw uses a frame-local autorelease pool. ## GPU follow-up: clip cost versus scene size (perf-gpu)

The pinned Zed renderer writes compact instance arrays and issues instanced draws
per scene batch, rather than a render pass per text row. Its monochrome shader
samples an atlas and checks a rectangular clip; it has no GPUIX ancestor rounded
clip traversal. Sources: [Z:metal_renderer.rs:1491](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui_apple/src/metal_renderer.rs#L1491),
[Z:shaders.metal:658](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui_apple/src/shaders.metal#L658).
The atlas backend uploads newly built tiles and deallocates removed tiles;
an instance record uploaded each frame is different from a glyph bitmap upload.
Sources: [Z:metal_atlas.rs:41](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui_apple/src/metal_atlas.rs#L41),
[Z:metal_atlas.rs:229](https://github.com/zed-industries/zed/blob/56934ec0560bce8929025497411de7f5322fb6ca/crates/gpui_apple/src/metal_atlas.rs#L229).
Zeron inherits these GPUI techniques through its pinned zui fork; the semantic
viewport work in T1/T3 bounds the instances that reach the renderer. These are
source comparisons, not a new benchmark of Zed or Zeron.

On the combined GPUIX tip, warm five-second diagnostics found only 13–21 ordinary
draws per frame, no path geometry and no atlas evictions across six scenarios.
Markdown/sidebar/thread/PR had zero bitmap uploads in that window. Streaming
added nine real backdrops (18 blur/composite draws); static scrolling had none.
The static scenes still repainted the 2560×1640 target, and approximately
98–99.9% of rounded glyph masks were provably interior to every rounded ancestor.
Thus the retained per-fragment rounded-chain evaluation was measurable waste;
per-row Metal passes and atlas eviction churn did not explain these workloads.

`native/patches/gpu_clip*` applies the rectangular fast path only to transient
upload copies with conservative device-pixel containment. It retains the exact
corner/edge shader, clips and transform semantics wherever that proof fails.
It does not remove rounded corners, materials, glyphs or motion. See
[`gpu/RESULTS.md`](gpu/RESULTS.md) for the paired measurements, frame-tail caveat,
pixel proof and remaining full-window/blur work. Hardware fragment/overdraw
counters and real 120Hz presentation remain unmeasured.
